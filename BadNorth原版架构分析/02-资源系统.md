# 02 · 资源系统

> **本文档目标**：解析 Bad North 的资源加载机制——从 ScriptableObject 定义到运行时的 ResourceList\<T\> 索引与本地化文本查找。

---

## 1. 系统目标

Bad North 的资源系统解决以下问题：
- 通过 Unity 的 ScriptableObject 定义游戏数据（升级、英雄类型、语音等）
- 运行时通过 `Resources.LoadAll<T>()` 自动扫描并建立静态索引
- 提供基于名称键的 O(1) 查找
- 通过 I2 Localization 插件处理多语言文本

## 3. 核心类

### 3.1 ResourceList\<T\> — 泛型资源容器

**文件**: `Assembly-CSharp/ResourceList.cs`（31行）

```csharp
public static class ResourceList<T> where T : UnityEngine.Object
{
    public static readonly Dictionary<string, T> dictionary = new Dictionary<string, T>();
    public static readonly List<T> list = new List<T>();

    static ResourceList()
    {
        T[] array = Resources.LoadAll<T>(string.Empty);
        foreach (T t in array)
        {
            ResourceList<T>.dictionary.Add(t.name, t);
            ResourceList<T>.list.Add(t);
        }
    }

    public static T Get(string key)
    {
        T t;
        return (!ResourceList<T>.dictionary.TryGetValue(key, out t)) ? null : t;
    }
}
```

**关键机制**：
- 静态构造函数在首次访问时自动触发 ✅ `ResourceList.cs:9-17`
- 调用 `Resources.LoadAll<T>(string.Empty)` 扫描 Resources 目录下所有 T 类型资源 ✅ `ResourceList.cs:11`
- 以 `t.name`（Unity Object 名称）为键建立 Dictionary 索引 ✅ `ResourceList.cs:14`
- `Get(key)` 提供 O(1) 查找

### 3.3 I2 Localization — 文本系统

**目录**: `Assembly-CSharp/I2/`

HeroUpgradeDefinition 和 HeroUpgradeType 中的文本字段（`nameTerm`, `descriptionTerm` 等）使用的是 I2 Localization 插件中的 `TermsPopup` 标记 ✅。运行时通过 `ScriptLocalization.Get()` 获取本地化文本 ✅ `HeroUpgradeDefinition.cs:78`。

## 4. 数据流

```
[Unity Editor]
  创建 ScriptableObject 资产（.asset 文件）
       ↓ 放在 Resources 目录
[游戏启动]
  ResourceList<T> 静态构造
       ↓ Resources.LoadAll<T>(string.Empty)
  Dictionary<string, T>  +  List<T>
       ↓
[运行时查找]
  ResourceList<T>.Get("资产名称")
       ↓ 返回 T 实例
  例如：
  SerializableHeroUpgrade 反序列化时：
      PostLoad → ResourceList<HeroUpgradeDefinition>.Get(name) ✅ SerializableHeroUpgrade.cs:112

[文本显示]
  定义中的 nameTerm 字段
       ↓ ScriptLocalization.Get(term)
  UI 显示本地化文本
```
